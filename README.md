# Predicting and monitoring local development from outer space

A self-contained Quarto reveal.js conference talk on reading Bolivian municipal development from
satellite imagery — 24 slides, about 20 minutes, ending on the Thank-you cover with no appendix.
Everything needed to view it, render it, regenerate every figure, and verify every number it
asserts is in this repository.
Nothing here reaches outside this folder.

The talk draws on the working paper *Predicting and monitoring local development from outer space:
Evidence from the Bolivian municipalities* (Carlos Mendez, Nagoya University).
It was extracted from that project's repository, [`project2026e`](https://github.com/quarcs-lab/project2026e), and the inputs it depends on travel with it as a frozen snapshot in [`sources/`](sources/).

## Quick start

**View it.** The rendered deck is published to GitHub Pages at
<https://quarcs-lab.github.io/project2026e-slides/>. There is nothing to install.

**Render it.** Needs Quarto and nothing else — the deck has no executable code cells.

```bash
quarto render monitoring-local-development.qmd     # -> index.html (~25 MB, self-contained)
```

**Regenerate a figure.** Needs Python. `uv sync` once, then:

```bash
uv sync
uv run python scripts/fig-r2-master.py             # one figure
for f in scripts/fig-*.py; do uv run python "$f"; done   # all of them
```

**Verify it.** Four independent checks; see [Verification](#verification) for what each one proves.

```bash
uv run python scripts/_source_checks.py .          # Tier S  — every number vs its source
uv run python scripts/_qa_checks.py .              # Tier B  — contrast, figure fit, overflow
uv run python scripts/_html_checks.py .            # Tier B' — the rendered HTML
uv run python scripts/_sync_check.py .             # the sources/ snapshot is intact
uv run --extra qa python scripts/_browser_checks.py . all   # Tiers A/A'/C — the live page
```

## Delivery

The deck ships as **one self-contained file**. `embed-resources: true` plus
`output-file: index.html` produce a single ~25 MB `index.html` with every image, font and script
base64-inlined: it works offline, it emails, and GitHub Pages serves it from the repository root
with no configuration.

**There is no chalkboard, and that was a deliberate trade.** Quarto cannot bundle the chalkboard
plugin's assets into a self-contained file, so `chalkboard: true` and `embed-resources: true` are
mutually exclusive. Portability won. To get the annotation tools back for one venue, make exactly
this change and accept a folder instead of a file:

```diff
-    embed-resources: true
+    embed-resources: false
+    chalkboard: true
```

Delivery then becomes `index.html` plus an `index_files/` folder of about 8 MB and 117 files, and
both have to travel together.

**`index.html` is committed.** There is no CI: GitHub Pages serves the file exactly as it sits on
`main`, so a fresh clone can present straight away. The cost is history. Base64 does not
delta-compress, so every commit that re-renders the deck adds up to ~25 MB of permanent history.
Batch slide edits into fewer rendered commits rather than committing `index.html` after each one.

Audience keys during the talk: `M` menu · `O` slide overview · `F` fullscreen. `S` opens the
speaker view, which is currently empty because the deck carries no notes.

## Paths

Every path in this deck resolves **relative to this folder**, through one module:
`scripts/_paths.py`. Nothing counts directory levels upward.

That is not stylistic. The scripts used to open with `ROOT = Path(__file__).resolve().parents[3]`,
which silently assumed the deck sat exactly three levels below a research repository — in eleven
files at once. Moving the folder anywhere broke all eleven, and not loudly.

`_paths` resolves each input in a fixed order: a live manuscript checkout if you name one, then
the vendored snapshot, then Hugging Face for the single file too large to vendor. It raises with a
message naming the file and every place it looked, rather than returning a path that does not
exist.

```bash
# Track the live paper instead of the snapshot (needs a project2026e checkout):
DECK_SOURCE_ROOT=/path/to/project2026e uv run python scripts/fig-r2-master.py

# Refuse the network and fail fast — proves a figure needs no download:
DECK_NO_NETWORK=1 uv run python scripts/fig-pop-raster.py
```

When you write a new figure script, take paths from `_paths.table()`, `_paths.data()` and
`_paths.cache()`, write output through `_paths.figure()` or `_paths.derived()`, and never compute
`parents[N]` above the deck folder.

## The provenance chain

The talk quotes about sixty numbers. Each one is traceable:

> the paper's analysis → `tables/*.csv` and the manuscript prose → `numbers.toml` → the slide

`numbers.toml` names, for every number the deck asserts, the exact cell it came from, and
`_source_checks.py` re-reads that cell. When a table is regenerated, a rounding-compatible change
still passes and a real change fails loudly with both numbers.

Fifteen of those numbers are stated in the paper's *prose* and appear in no table cell. The
manuscript text does not ship with this deck, so those are frozen in
[`sources/claims.toml`](sources/claims.toml) as a value, a line number, and the sha256 of that
line. Given a manuscript checkout, `--root` re-runs the original patterns against the live paper
and distinguishes *the number changed* from *the prose moved*.

## Verification

Four surfaces fail independently, so each has its own check. A deck is only delivered on an
overall pass.

| Tier | Command | What it proves | What it does **not** prove |
| --- | --- | --- | --- |
| **S** — the numbers | `_source_checks.py .` | Every number on a slide matches the cell or frozen claim it declares. Fail-closed: a missing manifest, an unaccounted number, or a missing `claims.toml` all fail. | That the *right* cell was declared. Point an entry at the wrong cell and it verifies the wrong number happily. |
| **B** — the source | `_qa_checks.py .` | WCAG-AA contrast of every theme colour, figure-vs-canvas fit, per-slide overflow risk, figure palette drift. | Diagnostic: it exits 0 even when it reports findings. Read the `QA SUMMARY:` line. |
| **B′** — the artifact | `_html_checks.py .` | The rendered HTML exists, is fresh, has reveal.js structure, wired every feature the `.qmd` asks for, and **every figure resolved** — inlined payloads are checked for real content. | Nothing about how the page behaves once JavaScript runs. |
| **A/A′/C** — the live page | `_browser_checks.py . all` | Fonts actually loaded *and are actually rendering*; per-slide screenshots; a PDF with dark backgrounds intact. Needs Chrome. | — |
| snapshot | `_sync_check.py .` | The frozen inputs are intact and complete. With `--root`, whether upstream has moved and **which side moved**. | — |

**A green Tier S is not proof the deck is right.** It cannot see double rounding, and there it
does worse than fail — it certifies. The check re-rounds the *source cell*, so when the cell is
itself already rounded the result can differ from rounding the full-precision value once:

```
published table stores 0.795  →  round to 2 dp  →  0.80   ← what Tier S will certify
the figure computes  0.79479  →  format to 2 dp →  0.79   ← what the audience sees
```

Two numbers in this deck sit on that edge; `numbers.toml` flags both. When a source table carries
fewer decimals than the figure computes from, quote it at the table's own precision or not at all.

**Tier B's overflow flag is a character count, not a measurement,** and it is wrong in both
directions. It counts raw source characters, HTML tags included, and gives `.cards` slides no extra
allowance (only `.columns` slides get one). So it flags the outcome-variable, methods and
concluding slides, all of which fit. It also cannot see a composition that overflows even though
each element is short. The first draft of the concluding slide passed the count and measured
732px against the 720px canvas. The only real test is the browser: open the slide at 1280×720 and
check that `scrollHeight` is at most 720. The screenshots from `_browser_checks.py . shots` show
the same thing.

**Tier S failing and `_sync_check` failing are different problems.** Tier S says the *deck* is
wrong — fix the slide or the manifest. `_sync_check` says the *paper* moved, or that someone
edited the frozen snapshot — neither is a deck bug, and the fix is upstream.

## `sources/` — the frozen snapshot

`sources/` holds a copy of every input the deck needs: nine result tables, nine pickled model
fits, municipal geometry, two rasters, and seven Python modules from the manuscript's `code/`.
It mirrors the source repository's own layout, which is what lets the vendored `hf_data.py` work
unedited.

[`sources/README.md`](sources/README.md) is the full story, including three things that will
otherwise surprise you: why the pickles live in `notebook-cache/` and not `.notebook-cache/`, why
only the seven `.py` files carry a provenance banner, and why the vendored modules must be
imported flat rather than as a package. `sources/PROVENANCE.toml` records a sha256 and the
originating commit for all 33 files.

Refreshing it is deliberately a manual two-step: `_sync_check.py --root <checkout>` tells you what
moved, you copy what you want, then `--freeze` re-records it. Freezing never copies files, so it
cannot quietly overwrite a copy that was pinned on purpose. **After refreshing, rebuild every
figure and re-run Tier S** — a stale figure beside a fresh number is exactly the failure these
checks exist to catch.

## The one file that is not vendored

`data/nighttimeLights/rasters/bolivia_ntl_viirs_2017.tif` is 118 MB, over GitHub's 100 MB
per-file limit. It streams from the public Hugging Face dataset
[`cmg777/project2026e`](https://huggingface.co/datasets/cmg777/project2026e) on first use and
caches under `~/.cache/huggingface`; the download takes about 20 seconds and happens once. No
token is needed.

It affects **two figures only** — `scripts/fig-ntl-raster.py` and one panel of
`scripts/fig-data-layers.py`. Every other figure builds offline from the snapshot, and
`DECK_NO_NETWORK=1` proves it. Offline, those two fail with a message naming the file and both
remedies rather than a traceback.

## Figures

Every figure on a slide is generated by a script in `scripts/`, from the snapshot. The mapping is
the figure table in [`outline.md`](outline.md).

```bash
uv run python scripts/fig-r2-master.py            # main variant
uv run python scripts/fig-r2-master.py simple     # a script may take a variant argument
uv run python scripts/fig-views-lisa.py sdg7      # or a goal slug: sdg1 | sdg7 | sdg13
```

`fig-views-lisa.py` and `fig-views-choropleth.py` print
`verified against tables/tbl-views-comparison-<slug>.csv: all statistics match the manuscript`
before writing anything. That line is the single most valuable assertion in the pipeline: it means
the vendored pickles, geometry, spatial weights and tables are all mutually consistent. It is not
optional and not tolerance-tuned — for eight days this deck shipped Moran's *I* and hot/coldspot
shares off by up to seven points because nothing compared them to anything.

**This deck's figure conventions are its own.** A dark transparent canvas, SVG for charts, PNG for
maps, `savefig.dpi = 192`, and `FIGSIZE = (7.0, 7.9)` at `DPI = 280` for the raster panels
(`scripts/_rasters.py` explains why that unusual aspect is correct). The parent research project
uses 6×4 inches at 300 DPI for journal figures; that convention does **not** apply here. Do not
"standardise" them.

**Figure output is byte-reproducible, within one environment.** `_palette.py` fixes matplotlib's
`svg.hashsalt` and `SOURCE_DATE_EPOCH`, so regenerating an unchanged figure produces a zero-byte
diff. Without that, every rebuild showed ~54 lines of changed clip-path ids plus an embedded
timestamp, which is how a real change gets missed.

That guarantee stops at the matplotlib version, and the boundary is worth knowing before you go
hunting: **matplotlib output is not byte-stable across versions — not even patch versions, and not
even for SVG.** Between 3.10.9 and 3.11.1 text metrics shift enough that `bbox_inches="tight"`
crops to a different canvas height (394.33 pt vs 401.05 pt) and every path coordinate moves, for a
~1,000-line diff in a visually identical chart. `uv.lock` pins the exact version, so the committed
figures reproduce byte-for-byte for anyone who runs `uv sync` — and only for them.

So a large figure diff after changing environments means nothing, and the authoritative check is
never the bytes. It is `verify_against_paper()` plus Tier S, both of which compare *numbers*.

Three figures in `figures/` are third-party or AI-generated rather than computed;
[`figures/README.md`](figures/README.md) documents each one's provenance, prompts and licensing.

## Fonts

The two bundled webfonts are declared in `fonts.html` and injected into the document head via
`include-in-header`. **They must stay there.** Quarto compiles `theme.scss` into
`libs/revealjs/dist/theme/`, and a relative `url()` inside a stylesheet resolves against *the
stylesheet* — so `url("fonts/Inter-Variable.ttf")` written in `theme.scss` looks for
`.../dist/theme/fonts/Inter-Variable.ttf`. That directory really exists, because reveal.js ships
its own fonts there, which makes the 404 look like a working path while the deck falls back to a
system font. No error, no warning. This deck already shipped that bug once.

Each `@font-face` names its file exactly once. It used to list the same file twice, for two
`format()` hints, and under `embed-resources: true` pandoc inlined both copies — 2.8 MB of pure
duplicate. Do not re-add the second `url()`.

Because the failure is silent, it gets a runtime check rather than a grep:

```bash
uv run --extra qa python scripts/_browser_checks.py . fonts
```

That probe measures each family against monospace in a real browser — a missing font substitutes
rather than erroring, so the width delta is the only honest signal — and includes a nonexistent
family as a control, which must measure exactly 0. If the control is not 0 the measurement is
meaningless and the probe says so.

One known limit: matplotlib renders only a variable font's *default instance*, so every weight
resolves to Regular in figures. Figure hierarchy has to come from size, not weight.

## Deploying

GitHub Pages is set to **Deploy from a branch: `main`, `/` (root)**. There is no workflow and no
build step on GitHub: whatever `index.html` is committed is what the audience sees, a minute or so
after the push. That makes the local render the release step, so do these in order:

1. `quarto render monitoring-local-development.qmd`
2. Run the checks from [Verification](#verification). Tier B′ in particular confirms the file is
   fresh and that every figure was inlined. A linked-resources render is ~70 KB and looks perfect
   locally, because `figures/` sits right beside it, then shows broken images on Pages.
3. Commit the `.qmd` and `index.html` together, then push.

Committing a `.qmd` change without re-rendering publishes nothing, and the live deck quietly goes
on showing the old version.

## Known limits

- **No chalkboard.** The cost of single-file delivery; see [Delivery](#delivery).
- **`index.html` is about 25 MB** and takes a few seconds to open on a slow connection. About
  3.6 MB of that is one 3-panel map used on two slides, which pandoc inlines twice — the cost of
  a deliberate callback. Because the file is committed, each re-render grows the repository's
  history by about that much.
- **Tier S cannot see double rounding**, and certifies rather than failing. See
  [Verification](#verification).
- **Tier B's overflow heuristic misfires** on HTML-primitive slides and misses composition
  overflow. Measure in a browser. See [Verification](#verification).
- **`_qa/` is about 40 MB** of regenerable screenshots and a PDF. It is *not* gitignored: 25 files
  from the initial upload are tracked, and they now show the pre-appendix-removal deck. Leave local
  regenerations unstaged.
- **`numbers.toml` still declares some numbers that no slide shows any more** (from the removed
  appendix and earlier cuts). Tier S does not flag unused entries, so they are harmless, but a
  stale `claim` label is not evidence that the number is on screen.
- **Figure weights are all Regular** in matplotlib. See [Fonts](#fonts).
- **Two dependencies look removable and are not.** `contextily` and `scikit-learn` are imported at
  module level by vendored files the deck never calls into; `pyproject.toml` says so at the point
  of temptation.
